# M10 section 8: C# application hosts over the C++/CX component

## Ownership decision

Application shells are C# over the component's generated `WebKit.winmd`; engine, component and OS service projections remain C++/CX/native, and native diagnostic payloads remain native. The component WinMD is the only application-facing contract. The proof and target framework rules are recorded in `csharp-toolchain.md`.

## Task 8.2 C# MVVM browser controls

`BrowserViewModel.cs` owns bindable address/status, app-bar expansion, address-editing state, and projections of Source, DocumentTitle, CanGoBack, CanGoForward, IsLoading and consent readiness. XAML binds the bottom address bar, icon/text panel commands, transient status, and loading indicator; Back/Forward/Reload call public control methods through policy. Enter invokes NavigateCommand; system Back dismisses address editing or the menu before traversing history. The compact address field has a splitter before the dots button; focus hides compact controls, expands the editor, and dims the document. There are no tabs. Empty idle status is collapsed, and the app inherits system light/dark ThemeResource brushes rather than forcing Light or hard-coded chrome colors. Browser lifecycle/title/history events notify bindings.

The current integrated build uses version 1.0.0.4. ARM Release/.NET Native, metadata and compiled-XAML gates pass with zero warnings; generated type-provider/page-connector files construct WebKitWebView, including strongly typed overflow command bindings. The optional `-LayoutDiagnostics` flavor records the real Frame/Page/root/chrome/address geometry and six independent checks; the normal flavor compiles out that instrumentation. Full navigation-state binding against real engine signals awaits production page readiness/forwarding; the advertised engine capability mask is zero and default public initialization remains E_NOTIMPL.

## Task 8.3 C# BrowserPolicy

`BrowserPolicy.cs` mediates HTTP(S) remote navigation, app-owned markup, local demo markup, Stop and history/reload commands. The packaged `Assets/blocked.html` is selected after a valid LocalState override and before the built-in safe fallback; substitutions HTML-escape URI/title. `Assets/demo.html` remains opaque-origin HostHtml without a remote base. The ViewModel exposes explicit Proceed only after a failed Remote HTTPS navigation issues a token, the policy associates the subsequent HostHtml ID with that same token, and that HostHtml terminal completes successfully. Generic navigation/markup, Stop and null Source clear eligibility. The host never changes TLS verification policy.

The host-runnable rule suite passes **23/23**, covering URI scheme validation, escaping, override/package/fallback precedence, HostHtml-ID/token separation, completion gating, one-shot exact-object consumption, failed warning and generic-navigation invalidation. The integrated ARM Release/.NET Native package build passes with zero warnings, compiled XAML proof, blocked/demo assets in the signed AppX, and C++ component contract gates unchanged. The production engine still has no page capability; a complete remote/TLS/consent device run cannot pass until page forwarding is implemented.
